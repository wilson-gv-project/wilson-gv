Decisions and known limits
--------------------------
- B7 (2026-10-09): each term's motif has exactly one resonance point: number of conditions = number of axes
  = rank of the condition matrix. Checked when compiling (CompiledTerm.from_VibPertTerm, plan.py).
  Not supported: fewer conditions than axes (a line, E8), more conditions than axes. Malformed: conditions that
  contradict each other. A term without conditions passes: no spectrum, but its other parts can be computed.
- Denominators (2026-10-10): w is always the Hessian eigenvalue (nc_sqrt_eigval); an energy difference always
  uses the chosen states. derive's is_pert_wf_diff tells them apart (True: energy difference); to_str prints
  both alike, e.g. <['a'],[]>.
- states_choice must follow the vib analysis regime: GVPT2, VPT2 -> anharmonic; harmonic -> harmonic. The two
  differ in 272 of 340 formaldehyde coefficients. from_datadict cannot know the regime, so it has no default
  (2026-10-11): the caller passes the choice.
- No feature is dropped for its amplitude (2026-10-09), as in the old code. Weak features stay, and so do
  features whose rows cancel (a record: FeatureResult.cancelling(rel_tol) lists them). A term with coefficient 0
  never becomes a row (FeatureResult.zero).
- Linear polarization only (2026-10-11): get_pol_laser stores into a real array. A complex vector (circular light)
  loses its imaginary part with only a ComplexWarning, e.g. (1, i, 0)/sqrt(2) on all four slots gives (0, 0, 0).
  No complex conjugate for the detected field either. Before circular light is used: raise on complex input, then
  add the conjugates.
- Drawing by domains cuts each feature at its box (draw_window docstring). Formaldehyde, dynrange 100: 1.05 % of
  the max intensity. A weak peak next to a strong one in another domain can be 12-36 % off. The old code cuts
  the same way (C3).

F. Performance
--------------
[ ] F1  einsum for the averaged part, then maybe for the whole sum over summation labels. Only if F2 shows a need.
        Measured 2026-10-11 (random polgrad and dipgrad, rank 4, laser_pol (1, 1, 1)):
        - On the fly: 62 us per index set, for any number of modes. build_contributions asks for 12 n^3 + 2 n^2
          averages (14 EVV terms): 6 modes 0.17 s, 20 modes 6 s, 40 modes 50 s, 80 modes 6.4 min
          (time per call x number of calls).
        - One einsum per averaged expression, the whole n^3 tensor: 0.06 ms (6 modes), 0.12 ms (40), 0.44 ms (80).
          Memory n^3 x 8 bytes: 0.5 MB at 40 modes. On formaldehyde it gives the on-the-fly values (all 14 terms,
          every index set, 3 polarizations) to 4e-16 of the largest value.
        - Why slow: per call, 21 recipe entries x 3 properties = 63 Python steps. Each step calls prop_trivname,
          searches MolPropsCollection one by one and reads one numpy element. The checks and an import inside the
          closure run on every call too.
        - Repeated work: terms 2-13 average the same product, polgrad (slots 0, 3) x dipgrad (1) x dipgrad (2), only
          with other labels (term 3 reads T[c, a, b], term 8 T[b, a, c]). One n^3 tensor could serve 12 terms.
          Terms 2, 4, 5, 7, 9-12 have an average without c, yet it is computed again for every c.
        - Averaging is about 70 % of build_contributions. The rest is about 27 us per index set, so about 20 s at
          40 modes. Its largest part is the deepcopy in FreqTermsCollection.__post_init__ (get_vibenedenom and
          get_pert_wf_diff build a new collection on every index set).
        Tests if F1 is done: einsum = on-the-fly value for every EVV term, every index set, 3 polarizations
        (rel 1e-12, abs 0); each term reads the tensor with its own labels (term 8: T[b, a, c], the B6 trap).
