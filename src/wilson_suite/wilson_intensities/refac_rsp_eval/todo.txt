Decisions and known limits
--------------------------
- B7 (2026-10-09): each term's motif has exactly one resonance point: number of conditions = number of axes
  = rank of the condition matrix. Checked when compiling (CompiledTerm.from_VibPertTerm, plan.py).
  Not supported: fewer conditions than axes (a line, E8), more conditions than axes. Malformed: conditions that
  contradict each other. A term without conditions passes: no spectrum, but its other parts can be computed.
- Denominators (2026-10-10): w is always the Hessian eigenvalue (nc_sqrt_eigval); an energy difference always
  uses the chosen states. derive's is_pert_wf_diff tells them apart (True: energy difference); to_str prints
  both alike, e.g. <['a'],[]>.
- states_choice must follow the vib analysis regime: GVPT2, VPT2 -> anharmonic; harmonic -> harmonic. The two
  differ in 272 of 340 formaldehyde coefficients. The data cannot know the regime, so nothing has a default.
  The data holds no choice (2026-10-12): MolSystemData.states holds every state set the source has, by choice
  (states['harmonic'], states['anharmonic']). The evaluation takes states_choice (compute_features,
  build_contributions, evaluate_term_coeff_sumover, evaluate_full_index_dict, otf_vibdiffdenom) and reads
  states[states_choice]. One loaded MolSystemData serves both choices. A choice the data lacks raises
  (MolSystemData.check_states_choice), e.g. 'GVPT2' or 'anharmonic' without anharmonic states.
- Excluded modes are removed everywhere (2026-10-13): evaluate_response_terms(exclude_modes=(5,)) uses mode 5
  neither as a resonance label (no row, no peak) nor as a value of a summed label, as if the molecule did not
  have it. So the other peaks change too. Modes count from 0, as in the data; an unknown mode raises
  (evaluate.included_modes). The old code (VibAnaSetup.exclude_modes) differs: no peaks either, but its sums
  dropped the mode only where the summed label is in the averaged part (its precalculated averaged tensors were
  0 there), e.g. EVV terms 2, 4, 5, 7, 9-12 still summed over it.
- No feature is dropped for its amplitude (2026-10-09), as in the old code. Weak features stay, and so do
  features whose rows cancel (a record: FeatureResult.cancelling(rel_tol) lists them). A term with coefficient 0
  never becomes a row (FeatureResult.zero).
- The data is the caller's job (2026-10-14): the evaluator takes a MolSystemData (molsys_data) and reads no file;
  it takes no DataOriginInfo and does not call wilson_data_obtainer. Loading belongs to wilson_system
  (MolSystemData.load, MolSystemData.from_datadict). The evaluator only says which properties the terms use:
  pipeline.prop_names(terms). evaluate_response_terms checks that molsys_data has them (MolSystemData.check_props).
- Linear polarization only (2026-10-11): get_pol_laser stores into a real array. A complex vector (circular light)
  loses its imaginary part with only a ComplexWarning, e.g. (1, i, 0)/sqrt(2) on all four slots gives (0, 0, 0).
  No complex conjugate for the detected field either. Before circular light is used: raise on complex input, then
  add the conjugates.
- Boxes by amplitude (E10, 2026-10-14): each feature is drawn on its own box, sized so that a cut tail changes the
  plot by about eps * floor at most (floor = max / dynrange, the faintest the plot shows). dynrange is the plot's,
  required. Measured: at most 0.13 floors with eps 0.1. Before E10 (and in the old code, C3) boxes ended at
  1/dynrange of each feature's own peak, drawn by domains: 0.8-7.7 floors, up to 100 % off at points the plot
  shows (formaldehyde, ACDM; dynrange 100-1000).
  The box size is a rule passed to draw_spectrum (box_rule, 2026-10-14): amplitude_half_widths (the above), or
  intensity_half_widths (the old code's rule, kept as an option). No rule drops a feature.
- Peak width (E5, 2026-10-13): propagator_param sizes both the drawn peak and its box. A box is sized with the
  largest peak width, on every axis; a width that grows away from the peak can still be cut off by the box.
  A width function gets only the VibDiff; if it ever needs the condition's axes, pass the ResCondKey too (the
  FIXME in eval_resonance_factor).

        Domains vs each feature on its own box:

H. Rules
--------
H1  Prefer deleting to designing. A new type, cache or optimization needs a measured reason,
    e.g. draw_window came with a test that measures how far it is from draw_all.
H2  Make an abstraction on the second real use, not the first. No base classes, no registries, no second
    orchestrator next to WilsonSimulation. Delete code instead of commenting it out.

    Not frozen yet: Box, SpectralFeature, SpectralWindow, RectangularDomain.

    since 2026-10-13. No test checks it. Decide: move the translation into plan.py, or drop the rule.
