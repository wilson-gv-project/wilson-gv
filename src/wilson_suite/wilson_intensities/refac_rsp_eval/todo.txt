H. Rules (kept from the old README, removed 2026-10-09)
--------------------------------------------------------
H1  Prefer deleting to designing. A new type, cache or optimization needs a measured reason.
    e.g. draw_all came first; draw_window came with a test that measures how far it is from draw_all.
H2  Make an abstraction on the second real use, not the first. Code that looks shared stays with its one
    user until a second user exists. No base classes, no registries, no second orchestrator next to
    WilsonSimulation. Delete code instead of commenting it out.
H3  Units in the name (gamma_cm1, coords_cm), converted once at the boundary, never guessed from the size
    of a number.
H4  Don't store a value that can be derived from other fields; frozen dataclasses where possible.
    e.g. the ±Γ box that SpectralFeature.__post_init__ used to build: dataclasses.replace rebuilt it and
    threw away the dressed box (removed in E2).
    Now not frozen: Box, SpectralFeature, SpectralWindow, RectangularDomain, PrecalculatedData.
H5  Validate when an object is built; check types only at entry points.
H6  plan.py runs, and its output can be checked, with zero molecular data. Now: test_plan.py.
H7  Never change derive's objects (VibPerturbedTerm and its parts). Now: test_pipeline.py checks that the
    caller's terms stay unchanged.
H8  One module imports wilson_derive. Now broken: plan.py, and pipeline.py (term_var_translate);
    plan.py's docstring still says "ONLY importer". No test checks it. To decide: move the translation
    into plan.py, or drop the rule.
