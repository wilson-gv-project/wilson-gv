Decisions and known limits
--------------------------
- One resonance point per term (B7, 2026-10-09): number of conditions = number of axes = rank of the condition
  matrix. Checked when compiling (CompiledTerm.from_VibPertTerm, plan.py). Not supported: fewer conditions
  (a line, E8) or more. Conditions that contradict each other: malformed. A term without conditions passes
  B7; decided 2026-10-15: it is a flat background, calculated and drawn (E12; today build_contributions raises).
- One resonance axis set per evaluation (2026-10-15): one evaluate_response_terms call, and its grid result, is
  for one set of axes, e.g. {A, B}. The input terms are checked first: all must resonate on the same axes
  (check_one_axis_set, E11). {A} and {B} are different sets. The caller splits the terms (terms_by_axis_set) and
  makes one evaluation per set. Limit: the measured signal is |sum of all amplitudes|^2, so the sets interfere;
  separate grid results do not add up as intensities. Adding sets on one grid (a smaller set copied along its
  missing axes): not planned.
- Mock data for what the reader cannot give (2026-10-15): the reader's limits (no hypgrad, states up to 3
  quanta) are not the evaluator's. Tests for 1D-4D use mock data (G10, test_dimensions.py).
- Denominators (2026-10-10): w is always the Hessian eigenvalue (nc_sqrt_eigval); an energy difference uses the
  chosen states. derive's is_pert_wf_diff tells them apart (True: energy difference); term_to_str (compat.py)
  prints both alike, e.g. <['a'],[]>.
- states_choice (2026-10-12) must follow the vib analysis regime: GVPT2, VPT2 -> 'anharmonic'; harmonic ->
  'harmonic'. No default: the data cannot know the regime (formaldehyde: 272 of 340 coefficients differ).
  MolSystemData.states holds every state set the source has; the evaluation reads states[states_choice].
  A choice the data lacks raises (MolSystemData.check_states_choice).
- Excluded modes (2026-10-13) are removed everywhere, as if the molecule did not have them: no peak, and not
  summed over, so other peaks change too. Modes count from 0; an unknown mode raises (evaluate.included_modes).
  The old code (VibAnaSetup.exclude_modes) still summed over them in EVV terms 2, 4, 5, 7, 9-12.
- No feature is dropped for its amplitude (2026-10-09), as in the old code. Weak and cancelling features stay
  (FeatureResult.cancelling(rel_tol) lists them). A term with coefficient 0 makes no row (FeatureResult.zero).
- The data is the caller's job (2026-10-14): the evaluator takes a MolSystemData, reads no file, and does not
  call wilson_data_obtainer. Loading: MolSystemData.load or MolSystemData.from_datadict (wilson_system).
  The evaluator names the properties the terms use (pipeline.prop_names(terms)) and checks that the data has
  them (MolSystemData.check_props).
- Linear polarization only (2026-10-11): get_pol_laser stores into a real array, so a complex vector (circular
  light) loses its imaginary part with only a ComplexWarning. No complex conjugate for the detected field
  either. Before circular light is used: raise on complex input, then add the conjugates.
- Boxes by amplitude (E10, 2026-10-14): each feature is drawn on its own box, sized so that a cut tail changes
  the plot by at most about eps * floor (floor = max / dynrange). The box rule is an input:
  draw_spectrum(box_rule=), amplitude_half_widths (new) or intensity_half_widths (the old rule). No rule drops
  a feature.
- Peak width (E5, 2026-10-13): propagator_param sizes both the drawn peak and its box. A box uses the largest
  peak width, on every axis; a width that grows away from the peak can still be cut off. A width function gets
  only the VibDiff; if it ever needs the condition's axes, pass the ResCondKey too (FIXME in
  eval_resonance_factor).

        get_pol_tensor (amplitudes/averaging.py, the recursive return line) builds the polarization product in
        reverse: slot k gets the polarization of slot n-1-k. derive numbers the slots 0 = detector, k = pulse k
        (dressWithPulseInteractions, response_terms.py). e.g. get_pol_laser([x, y, z]) gives [-1.0]; should be +1.

            return get_pol_tensor(np.kron(pol_tensor, np.array(pol[0])), pol[1:])

            refac_rsp_eval/tests/test_a15_polarization_order.py         5 fail until the fix; 2 pass

        1 control passes); not on this branch.
        With the fix applied in memory all of them pass, and nothing else changes.
        When it matters (checked 2026-10-15). An odd-rank average (3, 5) is built from the Levi-Civita tensor, so it
        changes sign in a mirror. It is nonzero only if both:
            - the molecule is chiral. An achiral one (a mirror plane or an inversion centre) gives 0: formaldehyde
              gives 0 for IR + vis SFG and for 3 IR + UV, even with fields along x, y and z;
            - three fields point along three different directions, not all in one plane. laser_pol at rank 3:
              0 for x x x, 0 for x, y and a direction between them, -1 for x y z (+1 after the fix).
        So at odd rank A15 matters exactly where there is a signal, and there its sign tells the two mirror images
        of the molecule apart. Odd rank in G7: IR + vis SFG (3); beta-alpha CARS, EVV + 2nd UV, every 3 IR + UV (5).
        Rank 6 (every 4 IR + UV setup) is even: nonzero for any molecule. There A15 can give wrong values unless the
        polarization list reads the same backwards (e.g. all along x).
        Ranks above 6 are not supported at all (G7: the 7-pulse setup has rank 8).

[ ] E10 Box size by amplitude. Code done 2026-10-14. Left: tune the knobs (later): tests/e10_boxes.py scores any
        knob setting against draw_all; add cases and knob values, then choose the defaults.
        The rule (features.amplitude_half_widths), from the plot's dynamic range D:
            floor = A_max^2 / D                                  the faintest the plot shows
            2 * A_max * tail(d) <= eps * floor                   a cut tail changes the plot by eps * floor at most
            tail(d) = a_f * gamma / sqrt(d^2 + gamma^2)          a_f = sqrt(get_intensity()): the feature's peak
            k = 2 * D * a_f / (eps * A_max);  d = gamma * sqrt(k^2 - 1);  k <= 1: 1 gamma
          gamma: the largest of peak_widths(), on every axis. A_max: each feature's amplitude at the nearest
          window point, the largest (0.4-10 % from the true max). Only eps / D counts, e.g. 0.1 / 500 = 2e-4.
          Knobs: dynrange (required), eps (0.1), min_gammas (1), max_cm (none; a cap breaks the eps bound),
          a_max (default: the estimate above).
          e.g. ACDM, D 500: a feature with 1e-2 of the max intensity gets the whole window; 1e-4: 470 cm-1;
          1e-6: 47 cm-1; 1e-8: 1 gamma.

H. Rules
--------
H1  Prefer deleting to designing. A new type, cache or optimization needs a measured reason (e.g. draw_window
    came with a test that measures how far it is from draw_all).
H2  Make an abstraction on the second real use, not the first. No base classes, no registries, no second
    orchestrator next to WilsonSimulation. Delete code instead of commenting it out.
H3  Units in the name (gamma_cm1, coords_cm), converted once at the boundary, never guessed from a number's size.
H4  Don't store a value that can be derived from other fields; frozen dataclasses where possible.
    Not frozen yet: Box, SpectralFeature, SpectralWindow, RectangularDomain.
H5  Validate when an object is built; check types only at entry points.
H6  plan.py runs, and its output can be checked, without molecular data (test_plan.py).
H7  Never change derive's objects (VibPerturbedTerm and its parts). test_pipeline.py checks it.
H8  "One module imports wilson_derive" is broken: plan.py and compat.py both do at run time; pipeline.py only for
    type hints (plan.py's docstring says so; no test checks it). Decide: move the translation into plan.py, or
    drop the rule.
